## 2. Constraint

- [ ] **CS-01 — Empty-title validation message**
 Actual: Submitting with an empty title does **not** create the task (correct), but **no validation message is ever shown**: the Create button simply stays disabled (Save disabled when `!title.trim()`), Enter does nothing, the title input has no `required` attribute, `handleSubmit` returns silently, and no toast/inline error/red border appears anywhere in the DOM.

  **🐞 Bug Report — CS-01**
  - **Title:** No validation feedback when attempting to save a task with an empty title
  - **Severity:** Medium (UX/feedback defect; data integrity is preserved)
  - **Preconditions:** "Add Task" dialog open.
  - **Steps:** 1) Leave Title empty. 2) Fill description/deadline/priority. 3) Click "Create Task" / press Enter.
  - **Expected:** Task is not created **and** a visible validation message prompts the user to enter a title.
  - **Actual:** Task is not created, but zero feedback is given — button remains disabled, no error text, no toast, no input highlighting.
  - **Evidence (DOM):** Save/Create button has `disabled` attribute while title is blank; no error/status elements rendered on submit attempt; Sonner toast container receives no event.

- [X] **CS-02 — Grayed-out Edit/Complete on blocked tasks**
 Actual: For tasks with incomplete prerequisites, the Edit (pencil) and Complete (circle) buttons are `disabled` with grayed styling (`text-muted-foreground/40 cursor-not-allowed`, Complete circle `opacity-50`); synthetic clicks on the disabled buttons have no effect. → Matches expected.

- [ ] **CS-03 — Only description/priority modifiable on locked tasks**
 Actual: For a locked task (e.g., "Complete tax filing", blocked by "Review project proposal"), **no field can be modified at all**: the Edit button is disabled (`disabled: isBlocked`, guard `onClick: () => !isBlocked && onEdit(task)`), there is no inline editing on the card, and the form's restricted-edit mode (which in code disables only title/deadline inputs, leaving description/priority editable) is unreachable because the dialog can never be opened.

  **🐞 Bug Report — CS-03**
  - **Title:** Locked tasks cannot be edited at all — description and priority are not modifiable
  - **Severity:** Medium-High (functional restriction beyond the intended constraint)
  - **Preconditions:** A task with an incomplete prerequisite (e.g., "Complete tax filing").
  - **Steps:** 1) Locate the blocked task card. 2) Attempt to open the Edit dialog (pencil button). 3) Attempt any inline edit on the card.
  - **Expected:** Only the locked fields (title/deadline) are read-only; description and priority remain editable.
  - **Actual:** The Edit button is disabled and grayed; no editing path of any kind exists for a locked task; description/priority can never be modified.
  - **Evidence (DOM):** Edit button carries `disabled` attribute and muted/cursor-not-allowed classes; guarded click handler verified in source; no inline inputs on cards.

- [X] **IX-02 — Dashed connection lines**
 Actual: All 5 dependency connections render as SVG paths with `stroke-dasharray="6,4"` (dashed) plus arrowhead markers (`url(#arrowhead)`), overlaid on the task board between prerequisite and dependent cards. → Matches expected.

- [ ] **IX-03 — Hover pop-up on the dashed connection line**
 Actual: Hovering directly on the dashed line (pointer verified on the line's 16-px hover path; the line's hover visual state activates — highlight, thicker stroke, active arrowhead) does **not** produce any visible pop-up. The tooltip opens logically (Radix state becomes `delayed-open`) and its content element **is** created in the DOM with correct chain data — but it is rendered **inside the `<svg>` element** (the app's `TooltipContent` has no Portal, and `DependencyLines` places each `<Tooltip>` as a child of the `<svg>`), where the browser never paints it: 0×0 px box, `position: static`, no rendered text. The invisible tooltip also never unmounts after the pointer leaves.

  **🐞 Bug Report — IX-03**
  - **Title:** Connection-line hover pop-up is never displayed (tooltip rendered inside the SVG)
  - **Severity:** High (feature is effectively missing for the user)
  - **Preconditions:** At least one dependency pair visible on the Active board.
  - **Steps:** 1) Move the mouse pointer onto the dashed line between a prerequisite card and its dependent card (e.g., between "Review project proposal" and "Submit final report"). 2) Wait 2–3 s. 3) Move the pointer away.
  - **Expected:** A pop-up appears showing the dependency chain details; it dismisses when the pointer moves away.
  - **Actual:** No pop-up appears at any point. Internally the tooltip state opens (`stateAttribute = "delayed-open"`) and a `div[data-radix-popper-content-wrapper]` with the correct chain text **is** inserted — but as a child of the `<svg>` overlay (HTML content inside SVG), it has a 0×0 bounding box, static position, and no rendered text, so it is invisible. On pointer move-away the invisible wrapper persists in the DOM (does not unmount).
  - **Root cause (verified in component source):** `src/components/ui/tooltip.tsx` renders `TooltipPrimitive.Content` without a `TooltipPrimitive.Portal` wrapper, while `DependencyLines.tsx` renders each `<Tooltip>` inside the `<svg>` element — so the pop-up is mounted in a non-renderable SVG context.
  - **Contrast:** The same tooltip system works correctly on task-card badges (HTML parent): hovering the "2 prerequisites incomplete" badge displays a real, visible 248×102 px fixed-position pop-up listing "Dependency Chain — Review project proposal (pending), Complete tax filing (pending)", and it unmounts on pointer move-away.

## 4. Content

- [ ] **CT-01 — Label correctly names bound prerequisites**
 Actual: For **single** bindings the label is exact: `Prerequisite "Review project proposal" incomplete` on "Complete tax filing". For **multiple** bindings the label shows only a count — "2 prerequisites incomplete" on "Submit final report" (bound to "Review project proposal" + "Complete tax filing") and on "Ship product launch" (bound to "Plan team lunch" + "Prepare slides") — **without naming any prerequisite titles**, so the label does not cover all prerequisites when several are bound. (Hovering the badge does open a visible tooltip that lists the names — but the label itself does not.)

  **🐞 Bug Report — CT-01**
  - **Title:** Multi-prerequisite label shows only a count instead of naming the bound prerequisites
  - **Severity:** Medium (content completeness defect)
  - **Preconditions:** A task bound to 2+ prerequisites (e.g., "Submit final report" ← "Review project proposal", "Complete tax filing").
  - **Steps:** 1) Inspect the label on the dependent task card.
  - **Expected:** The label names the bound prerequisite(s), covering all of them when several are bound.
  - **Actual:** Single binding: exact name shown. Multiple bindings: only "2 prerequisites incomplete" — no task titles in the label.
  - **Evidence (DOM):** Badge text extracted from dependent cards; prerequisite bindings confirmed via the dependency lines and the (badge-hover) tooltip listing both titles with "pending" statuses.

- [ ] **CT-02 — Hover pop-up lists each link of the dependency chain with correct titles/statuses**
 Actual: The pop-up **never appears** (same rendering defect as IX-03), so the chain details cannot be seen by hovering the dashed connection. The underlying tooltip DOM content **is** data-accurate — for the "Review project proposal" → "Complete tax filing" connection it contains "Dependency Chain — Complete tax filing: pending; Review project proposal: pending", which matches current data (both tasks active/incomplete) — but it is invisible (0×0 inside the SVG). Additionally: (a) the connections **into** "Submit final report" (RPP→SFR and CTF→SFR, whose pop-ups would list the full 3-task chain RPP→CTF→SFR) can never be hovered at all, because their invisible 16-px hover paths are completely overlapped by the RPP→CTF connection's hover path, which always wins hit-testing; (b) the rendered content is duplicated (each chain appears twice).

  **🐞 Bug Report — CT-02**
  - **Title:** Dependency-chain pop-up is not visible on connection hover, and the full-chain connections are not hoverable
  - **Severity:** High (core content of the dependency feature is inaccessible)
  - **Preconditions:** Multi-level chain "Review project proposal" → "Complete tax filing" → "Submit final report" present on the Active board.
  - **Steps:** 1) Hover the dashed connection in the chain. 2) Inspect the pop-up content. 3) Attempt to hover the connections leading into "Submit final report".
  - **Expected:** A pop-up appears listing each link of the chain with correct task titles and completion statuses matching current data.
  - **Actual:** No pop-up is displayed (content mounted inside the SVG at 0×0 px — invisible). The hidden content is accurate for the reachable connection (RPP→CTF: "Complete tax filing — pending", "Review project proposal — pending") but invisible to the user. The two connections that would show the full chain (RPP→SFR, CTF→SFR) are unreachable: their hover paths are entirely covered by the RPP→CTF line's hit path. Secondary defect: the chain content is rendered twice (duplicate "Dependency Chain" header and item list) in both line and badge tooltips.
  - **Evidence (DOM):** `div[data-radix-popper-content-wrapper]` elements found inside the `<svg>` with correct `textContent` but 0×0 bounding boxes and no rendered `innerText`; `elementFromPoint` at every gap confirms only the RPP→CTF hit path is topmost where paths overlap; badge tooltip (visible) shows the same ×2 duplication.
